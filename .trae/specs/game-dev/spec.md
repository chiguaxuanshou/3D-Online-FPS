# 3D射击游戏二次开发 - 产品需求文档

## Overview
- **Summary**: 基于现有Three.js多人3D射击游戏进行二次开发，添加用户注册登录、战绩统计、全球排行榜、新武器、房间系统、击杀回放等功能，并完成Linux服务器部署。
- **Purpose**: 将现有简易射击游戏升级为功能完善的在线多人竞技游戏平台。
- **Target Users**: 在线游戏玩家，追求多人对战、战绩追踪和竞技排名体验的用户。

## Goals
- 实现用户注册登录系统，支持JWT认证
- 添加战绩统计系统，记录K/D比、胜率、常用武器
- 实现全球排行榜功能（击杀榜/胜率榜/等级榜）
- 添加三种新武器：狙击枪、火箭筒、近战武器
- 实现房间系统（创建/加入房间、等待大厅）
- 添加击杀回放功能（记录最后10秒操作）
- 将后端服务部署到Linux服务器
- 配置Nginx反向代理+HTTPS+Systemd服务管理

## Non-Goals (Out of Scope)
- 不添加全新游戏模式（如团队战、夺旗模式）
- 不实现完整的商城交易系统
- 不开发移动端适配
- 不添加语音聊天功能
- 不实现AI敌人/机器人系统

## Background & Context
- 现有项目：基于Three.js、Socket.io、Node.js的多人3D射击游戏
- 当前功能：第一人称视角、WASD移动、鼠标瞄准射击、多人实时对战、基础碰撞检测
- 技术栈：Node.js后端、Socket.io实时通信、Three.js 3D渲染、原生前端JS
- 代码结构：app.js（服务端）、js/main.js（客户端）、index.html（页面）

## Functional Requirements

### FR-1: 用户注册登录系统
- **FR-1.1**: 用户可以注册新账号（用户名、密码）
- **FR-1.2**: 用户可以登录已有账号
- **FR-1.3**: 使用JWT令牌进行身份认证
- **FR-1.4**: 登录状态持久化（localStorage）

### FR-2: 战绩统计系统
- **FR-2.1**: 记录每场游戏的击杀数、死亡数
- **FR-2.2**: 计算K/D比（击杀/死亡）和胜率
- **FR-2.3**: 统计常用武器使用频率
- **FR-2.4**: 显示玩家等级（基于总击杀数）

### FR-3: 全球排行榜
- **FR-3.1**: 击杀排行榜（按总击杀数排序）
- **FR-3.2**: 胜率排行榜（按胜率排序）
- **FR-3.3**: 等级排行榜（按等级排序）
- **FR-3.4**: 排行榜数据实时更新

### FR-4: 新武器系统
- **FR-4.1**: 狙击枪：高伤害、低射速、瞄准镜功能
- **FR-4.2**: 火箭筒：范围伤害、延迟爆炸、低弹药量
- **FR-4.3**: 近战武器：近距离高伤害、无弹药限制
- **FR-4.4**: 武器切换功能（数字键1-3切换）

### FR-5: 房间系统
- **FR-5.1**: 创建房间（设置房间名、人数上限）
- **FR-5.2**: 加入房间（通过房间ID）
- **FR-5.3**: 等待大厅界面（显示房间内玩家列表）
- **FR-5.4**: 房主可开始游戏

### FR-6: 击杀回放
- **FR-6.1**: 自动记录最后10秒的操作数据（位置、视角、子弹轨迹）
- **FR-6.2**: 击杀后触发回放功能
- **FR-6.3**: 支持回放控制（播放/暂停）

### FR-7: 服务器部署
- **FR-7.1**: 后端Express+Socket.io服务部署到Linux
- **FR-7.2**: 配置Nginx反向代理
- **FR-7.3**: 配置HTTPS证书
- **FR-7.4**: 配置Systemd服务管理

## Non-Functional Requirements
- **NFR-1**: 游戏帧率保持在60FPS以上
- **NFR-2**: 网络延迟低于200ms时游戏体验流畅
- **NFR-3**: 数据存储采用SQLite，无需额外数据库服务
- **NFR-4**: 代码符合现有项目风格，遵循最小侵入原则

## Constraints
- **Technical**: 使用现有技术栈（Node.js、Socket.io、Three.js），不引入新框架
- **Business**: 单人开发，时间有限，优先核心功能
- **Dependencies**: 依赖已安装的socket.io和three包

## Assumptions
- 玩家数量不超过10人/房间
- 击杀回放仅记录本地数据，不依赖服务器存储
- 排行榜数据定期更新（非实时同步）

## Acceptance Criteria

### AC-1: 用户注册登录
- **Given**: 玩家打开游戏页面
- **When**: 点击注册按钮，输入用户名和密码
- **Then**: 账号创建成功，自动登录
- **Verification**: `programmatic`

### AC-2: 用户登录
- **Given**: 已有账号的玩家打开游戏页面
- **When**: 输入正确的用户名和密码
- **Then**: 登录成功，进入游戏主界面
- **Verification**: `programmatic`

### AC-3: 战绩统计显示
- **Given**: 玩家完成至少一场游戏
- **When**: 查看个人信息页面
- **Then**: 显示K/D比、胜率、常用武器、等级
- **Verification**: `human-judgment`

### AC-4: 排行榜显示
- **Given**: 服务器有玩家数据
- **When**: 点击排行榜按钮
- **Then**: 显示击杀榜、胜率榜、等级榜，数据正确排序
- **Verification**: `programmatic`

### AC-5: 武器切换
- **Given**: 玩家在游戏中
- **When**: 按下数字键1/2/3
- **Then**: 当前武器切换为对应武器，UI显示当前武器
- **Verification**: `human-judgment`

### AC-6: 狙击枪功能
- **Given**: 玩家装备狙击枪
- **When**: 右键瞄准并左键射击
- **Then**: 子弹伤害高，远距离精准命中
- **Verification**: `human-judgment`

### AC-7: 创建房间
- **Given**: 玩家已登录
- **When**: 点击创建房间，输入房间名和人数上限
- **Then**: 房间创建成功，进入等待大厅
- **Verification**: `programmatic`

### AC-8: 加入房间
- **Given**: 玩家知道房间ID
- **When**: 输入房间ID并点击加入
- **Then**: 成功加入房间，进入等待大厅
- **Verification**: `programmatic`

### AC-9: 击杀回放
- **Given**: 玩家击杀敌人
- **When**: 击杀发生后
- **Then**: 自动播放最后10秒的操作回放
- **Verification**: `human-judgment`

### AC-10: 服务器部署
- **Given**: Linux服务器已配置
- **When**: 执行部署脚本
- **Then**: 服务正常启动，通过HTTPS可访问
- **Verification**: `programmatic`
